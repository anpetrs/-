# Календарь писательниц

Сайт-календарь дней рождения русских писательниц и поэтесс. Статический, без зависимостей.

- **Календарь** — сетка месяца, карточка писательницы на каждый день (фото, годы жизни, справка, фрагмент текста со ссылкой на полную версию).
- **Год** — тепловая карта «месяц × день»; клик по месяцу — список, клик по дню — карточки.
- **Подписка** — `calendar.ics` (Google / Apple / Outlook, ежегодное повторение) и `feed.xml` (RSS), плюс ссылка на Telegram-канал.
- **Автор дня** — в дни без дней рождения показывается случайный текст случайной писательницы со ссылкой на карточку автора. Выбор делается при каждом открытии дня, кнопка «Другой текст» меняет его. В RSS «автор дня» выбирается заранее и фиксируется за дату: иначе записи за прошлые дни менялись бы при каждой пересборке.

## Правила дат

Дата в календаре выбирается по цепочке: **день рождения → день смерти → дата первой публикации → 8 марта**.
На карточке и в ICS это явно подписано («День памяти», «Первая публикация», «8 Марта»); на сетке такие писательницы — с пунктирной рамкой.
29 февраля в невисокосные годы показывается 28-го.

## Как добавить писательницу

Всё в `data/writers.json`:

```json
{
  "id": "tsvetaeva",
  "name": "Марина Цветаева",
  "realName": "",
  "born": "1892-10-08",
  "bornNote": "26 сентября по старому стилю",
  "died": "1941-08-31",
  "firstPublished": null,
  "photo": "photos/tsvetaeva.jpg",
  "bio": "Короткая справка.",
  "telegram": "https://t.me/ваш_канал/123",
  "texts": [
    { "title": "Название", "kind": "poem", "year": 1913, "text": "Строки…", "url": "https://…/полный-текст" }
  ]
}
```

- Даты: `"ГГГГ-ММ-ДД"`, `"ГГГГ"` (только год) или `"--ММ-ДД"` (день и месяц без года). Неизвестно — `null`.
- **Даты до 1918 года пишите по старому стилю** (как в Вики: «26 сентября (8 октября)» → `1892-09-26`). В календаре писательница стоит на дне по старому стилю, а день по новому стилю сайт считает сам и показывает в подписи («по новому стилю — 8 октября»).
- `wiki` — ссылка «читать о ней» (необязательно). Если не указана, ведёт на поиск Википедии по имени, который сразу открывает статью. `tgPost` — номер поста в канале, только для служебных целей, на сайте не показывается.
- Стихи показываются на сайте **целиком**, без ссылок. У прозы показывается начало, а в `url` обязательно ссылка на сайт с текстом или магазин (не на поисковик; сборка не пропустит).
- `kind` текста: `"poem"` или `"prose"`. «Автор дня» выбирается среди всех текстов, поэтому чем их больше, тем реже повторы.
- Фото: если `photo` не задано, браузер посетителя сам берёт миниатюру из статьи Википедии (с подписью «Фото: Википедия»); нет статьи или фото — инициалы. Свои фото кладите в `public/photos/` и указывайте путь в `photo`: они важнее.
- Сборка проверяет данные и падает с понятным сообщением, если что-то не так.

Настройки сайта (название, ссылка на Telegram-канал, адрес) — `data/config.json`.

## Импорт из Telegram

```bash
node scripts/import-telegram.mjs путь/к/выгрузке/messages.html [--photos] [--dry]
```

Скрипт читает посты «… родилась …» и стихи под ними, **добавляет** в `data/writers.json` тех, кого там ещё нет (существующих не трогает), и пишет `data/import-report.md`. С `--photos` копирует фото постов из папки `photos/` рядом с `messages.html`.

Канал писал даты то по новому, то по старому стилю, поэтому стиль каждого поста определяется так: явная пометка «по старому/новому стилю» → сдвиг на 11–13 дней между постами об одной писательнице → иначе по дате поста (с поста №2075, февраль 2024, считается старым стилем). Всё, что определено только по последнему правилу, помечено в `dateReview` и в отчёте — эти даты стоит проверить. Ручные поправки (имена, псевдонимы, даты, справки) — в `data/import-overrides.json`: `textFixes` (убрать или заменить стихотворение по номеру поста), `extraTexts` (добавить текст писательнице), `skipPosts` (не брать пост). Стихи с подписью «🖋 Автор» проверяются: если фамилия в подписи не совпадает, текст пропускается и попадает в отчёт.

## Запуск и публикация

```bash
npm test        # тесты
npm start       # сборка + http://localhost:8080
npm run build   # сборка в dist/
```

Публикация: GitHub → Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml` собирает сайт при пуше в `main` и раз в сутки (чтобы RSS был свежим).

## Авторские права

Тексты авторов, умерших менее 70 лет назад (то есть после 1955 года), охраняются. Показывайте только короткие цитаты со ссылкой на источник.
